# Technical Design — Atlas11 MVP Completion

## Overview

Atlas11 will complete one reliable, local-first coordination workflow: a planner submits the fixed seeded proposal, the API persists it, a review is run and streamed as validated SSE events, an approver records a coordination-only sign-off, and the map focuses a high-need district without changing funding data. The canonical integration gate is `scenario_key=demo-city-transit-01` with `proposal_id=demo-proposal-01`. In `DEMO_MODE=cached`, that route must work with no AWS, Bedrock, Chroma, or local embedding-model dependency and must return exactly one `OVERLAPPING` verdict, one `COMPLEMENTARY` verdict, and a `CO_FINANCE` memo. Approval and redirect are never a payment, allocation, commitment, or funding outcome.

The locked stack is Python 3.11+, FastAPI/Uvicorn, Pydantic v2, SQLite, Strands Agents SDK, ChromaDB, Bedrock Nova Pro/Titan V2, and React 18 + Vite + strict TypeScript + Tailwind CSS + Leaflet/react-leaflet. The new frontend will pin exact versions: `react@18.3.1`, `react-dom@18.3.1`, `vite@5.4.10`, `@vitejs/plugin-react@4.3.4`, `typescript@5.6.3`, `tailwindcss@3.4.14`, `postcss@8.4.47`, `autoprefixer@10.4.20`, `leaflet@1.9.4`, `react-leaflet@4.2.1`, `@types/leaflet@1.9.12`, `vitest@2.1.3`, `@testing-library/react@16.0.1`, `@testing-library/user-event@14.5.2`, `@testing-library/jest-dom@6.6.3`, and `fast-check@3.23.1`. Python requirements will add pinned `fastapi`, `uvicorn`, and the compatible pinned Strands SDK needed by `agent/clash_agent.py`; their exact released versions are selected once in `requirements.txt` and captured by the implementation lock/environment, rather than using ranges. No state-management framework, hosted datastore/vector service, UI framework, or payment integration is introduced.

## Chosen architecture and durable review execution

`agent/app.py` becomes an application factory with injected paths/services for tests and default production paths rooted at the repository. It owns HTTP validation, response mapping, CORS for `http://localhost:5173`, review orchestration, and SSE transport. `agent/store.py` remains the only SQLite writer for proposals, reviews, approvals, events, and audit rows. `agent/gaps.py` stays a read-only loader. React is a strictly typed consumer: API and stream bodies are untrusted until runtime parsers accept them.

The earlier lazy-first-SSE execution approach is retained but made durable and reconnect-safe. `POST /proposals/{proposal_id}/review` creates a `PENDING` review only; it does no cache, Bedrock, Chroma, or provider work. The first stream request atomically claims `PENDING → RUNNING` and starts `execute_claimed_review(review_id)` in an application-owned task that is deliberately independent of the HTTP response iterator. The task appends each event before publishing it. If the requesting browser disconnects, its iterator stops, but execution continues and a reconnect replays the persisted prefix then waits/polls for appended records until the terminal event. A reconnect never claims or starts another executor. A `RUNNING` review with no active local task is recovered by an explicit persisted lease: `reviews.execution_lease_expires_at` is set when claimed, renewed before each bounded operation, and may be atomically reclaimed only after expiry. The API logs a warning with the review ID before reclaiming. This prevents permanent `RUNNING` state after process/task cancellation while preserving one executor at a time.

`execute_claimed_review` uses a broad `try/except/finally`: normal completion atomically persists the validated report and sole `done`; any cache/tool/provider/model/database exception before completion calls idempotent `fail_review`, which atomically appends the sole `error`, marks `FAILED`, leaves the proposal `SUBMITTED`, and audits the factual failure summary. Cancellation is caught at the task boundary and also calls `fail_review` before re-raising. If final event serialization/yield fails after durable completion, no state is undone; reconnect replay remains available. A review is terminal only if its persisted execution status is `COMPLETED` or `FAILED` and it has exactly one terminal event. The stream emits persisted events in sequence; once it sends terminal `done`/`error`, it closes and sends no further state-changing event.

The implementation adds `execution_status`, `failure_message`, `execution_lease_expires_at`, and `updated_at` to `reviews`, and creates `review_events(review_id, sequence, event_json, occurred_at, PRIMARY KEY(review_id, sequence))`. Store methods are:

```python
create_review(...) -> ReviewCreated                 # PENDING only
claim_or_observe_review(review_id, now) -> ClaimResult
renew_review_lease(review_id, now) -> None
append_review_event(review_id, event, occurred_at) -> ReviewEventRecord
complete_review(review_id, report, events, now, audits) -> ClashReport
fail_review(review_id, message, error_event, now, audits) -> None
get_review_context(review_id) -> Proposal
get_review_execution(review_id) -> ReviewExecutionStatus
list_review_events(review_id, after_sequence=0) -> list[ReviewEventRecord]
```

Each changing method uses `BEGIN IMMEDIATE`. Claim/reclaim updates only `PENDING` or expired `RUNNING`; `complete_review` accepts only the owning `RUNNING` review, appends/preserves exactly one `done`, writes report JSON, changes the proposal `SUBMITTED → REVIEWED`, and marks `COMPLETED` in one transaction. `fail_review` is idempotent when already `FAILED`, never overwrites a completed review, and records no duplicate terminal event. A failed review remains an audit-visible failed attempt; because the original proposal remains `SUBMITTED`, the planner can create a new review after correcting the input/cache/service issue.

## Shared contracts, provenance, registries, and cache identity

`agent/schemas.py` is the source of truth. It retains existing canonical-ID and finite-number checks and gains `ReviewExecutionStatus`, `ReviewEventRecord`, `ReviewCandidateDetail`, `ReviewReportResponse`, `SearchRequest`, `ApiErrorResponse`, and cache models. `ProposalCreate` and `Proposal` gain `source_url: HttpUrl | None` (serialized as a string); user proposals may omit it. The canonical seeded proposal must provide `source_url="seeded://atlas11/demo-city-transit-01"`, so its provenance is retained through cache, SQLite `payload_json`, API, TypeScript parsers, and UI. Seeded source URLs are visibly presented as demo provenance, not an external evidence link.

`Memo.redirect_district_id` is valid for `CO_FINANCE` and `REDIRECT`, not only `REDIRECT`. Its field documentation and all UI copy define it solely as a coordination/map-focus target. `ClashReport` requires unique candidate IDs; `CachedScenario` further requires exactly two candidates, one of each required label, `source="seeded"`, `CO_FINANCE`, and a non-null known redirect district. `ApprovalCreate` strips `reason` and rejects empty rejections. Every public payload, tool input/output, cache record, database JSON rehydrate, REST response, and event payload is Pydantic validated.

Cache identity uses **semantic normalized equality**, deliberately matching `ProposalCreate` behavior rather than making an unenforceable wire-byte promise. The POST body is first rejected for unknown fields by an endpoint-only raw-object key check, then parsed by `ProposalCreate` (`str_strip_whitespace`, dates, and declared defaults apply). The cache stores `proposal_id`, a `ProposalCreate` body, and the SHA-256 of its normalized `model_dump(mode="json", exclude_none=False)` canonical JSON. A seeded submission is accepted only when its parsed normalized body equals the cache proposal and its recomputed normalized fingerprint equals the cache fingerprint. Consequently whitespace-only changes and omitted/default-equivalent values are accepted as semantically equivalent; substantive normalized value changes, explicit `null` where it changes normalized value, unknown keys, and wrong/missing scenario identity return `422` with no durable write. Tests document the whitespace, default/omitted, explicit-null, and substantive-change cases.

```python
class CachedScenario(BaseModel):
    scenario_key: Literal["demo-city-transit-01"]
    proposal_id: Literal["demo-proposal-01"]
    proposal: ProposalCreate
    proposal_fingerprint: str
    report: ClashReport
    scripted_events: list[ScriptedReviewStep]
```

On accepted seeded intake, the service constructs a persisted `Proposal` exactly once from `CachedScenario.proposal`, `CachedScenario.proposal_id`, server UTC `submitted_at`, and `SUBMITTED`; it does not let a client supply the ID. At execution, all tools receive `store.get_review_context(review_id)`, i.e. this persisted proposal with ID and submitted time. The cached report’s `proposal_id`, event `done.payload.review_id`, persisted proposal, deterministic overlap input, audit rows, and response envelope must therefore all carry the canonical IDs.

`agent/registry.py` is the sole project/district lookup boundary. `load_project_registry()` reads `projects.csv` and optional `seeded_projects.csv`, validates each with `Project`, rejects duplicate/conflicting IDs across or within files, and returns an immutable `dict[str, Project]`. It preserves both provenance types; there is no source precedence because duplicate IDs are a fatal local-data error. `get_registered_project(project_id)` is mandatory for every project resolution path: `tools/get_project.py`, `tools/check_overlap.py`, candidate-detail report assembly, cached-scenario validation, and any coordinate lookup validation. It raises `ProjectNotFoundError` for a missing validated ID and `RegistryDataUnavailableError` for unreadable/invalid registry data. `search_similar_projects` receives a validated `SearchRequest`, uses its city/district/sector/date context, and returns only candidate IDs/scores; each resulting candidate is resolved through this same registry before model packaging.

`load_district_registry()` validates local GeoJSON plus `load_gap_records()` as complete datasets and requires identical canonical district IDs. GeoJSON properties must include `district_id`, `district_name`, and canonical `city_id`; implementation adds this metadata only to seeded/illustrative local demo assets and preserves their labelling. `load_city_registry()` is the union of canonical project city values and district `city_id` values. Proposal creation validates city membership and requires a supplied district to belong to that city. Unknown city/district is a client `422`; cache references to absent project/district are local data corruption and cause stream `error` with readable `503`-class detail, never a name-based fallback.

## Retrieval, providers, taxonomy, and live agent

`agent/retrieval.py` changes its public entry point to `search(request: SearchRequest)`. `SearchRequest` requires nonblank `query` up to 10,000 characters, `k` in 1–8, known `city_id`, nonblank sector, optional known `district_id`, and a complete optional `[implementation_start, implementation_end]`. An incomplete proposal date pair produces no retrieval date filter; a provided end before start is `422`. Retrieval validates the registry before Chroma, applies exact city/district and normalized exact sector filtering plus inclusive implementation intersection, excludes candidates with missing dates when an interval is requested, returns unique IDs in deterministic `(-score, project_id)` order, and bounds scores to `[0,1]`.

The existing index builder remains responsible for validation, separate seeded input, deterministic content hash, stale deletion, and atomic manifest publication. Local embeddings use the current `SentenceTransformer(..., local_files_only=True)` behavior and cannot silently download. Bedrock uses Titan V2 with 20-second connect/read bounds. Every live provider request builds a fresh `PipelineConfig` and boto3 session after reloading `agent/.env`; mapped `ExpiredTokenException`, `UnrecognizedClientException`, and `ExpiredToken` raise `CredentialsExpired`. REST failures return exactly `503 {"error":"AWS credentials expired. Refresh agent/.env from Workshop Studio."}`; an already-streaming review receives that exact message in its terminal error payload. Credentials and raw tokens never enter error bodies, audit text, or logs. `scripts/check_aws.py` independently tests configured Nova and Titan callability with bounded clients, reports only model ID/callability/token lifetime if available, and exits non-zero for unavailable service.

`agent/clash_agent.py` loads its sole Strands `Agent` prompt from `agent/prompts/clash_system.md`; no system prompt is inline. Each documented file in `agent/tools/` exposes Pydantic models and exactly one tool: search, registry-backed project lookup, overlap facts, district need, and memo draft. The orchestration resolves at most eight retrieval results and provides at most five fully resolved packages to Nova Pro. It time-bounds the complete model invocation at 20 seconds, parses `ClashReport`, retries once with validation feedback, then raises a readable invalid-output failure mapped to terminal stream error/HTTP 502 semantics. Cached execution constructs neither this service nor retrieval/provider clients.

`agent/taxonomy.py` owns post-model guardrails. It computes/uses canonical-ID geography first, inclusive implementation date overlap with exactly 12 calendar months slack at each endpoint second, and concrete output evidence third. Cross-city output can only be `COMPLEMENTARY` (sector relationship) or `UNRELATED`; same-city/different-district output is at most `OVERLAPPING` and requires explicit shared beneficiaries; missing/insufficient date evidence cannot establish `DUPLICATE`/`OVERLAPPING`. A duplicate requires concrete-output evidence and at least two fact-backed matching attributes. Insufficient evidence is downgraded to the less-severe permitted result with bounded confidence and an audit event. Deterministic tools calculate facts; the model does not guess them.

## Cached review, API, audit, and errors

`agent/demo_cache.py` reads `data/demo_cache/demo-city-transit-01.json` as UTF-8 and validates `CachedScenario`, its semantic fingerprint, its canonical IDs, both candidate registry resolutions/provenance, redirect district, and scripted event order before an execution can complete. Its scripted events are nonblank `status`, zero or more `tool_call` values with non-negative `ms`, then one event for each required verdict, followed by `done`; reports/candidate events are validated before persistence. Cache load/validation errors are recoverable: the executor persists exactly one readable terminal error, keeps the proposal submitted, and does not call live services.

API contracts are:

| Endpoint | Success | Failure / state rule |
|---|---|---|
| `POST /proposals` | `201 Proposal` | `422` malformed/unknown registry value/noncanonical seeded body; `409` existing generated ID; no write on failure. |
| `POST /proposals/{proposal_id}/review` | `202 ReviewCreated` | `404` unknown; `409` if not `SUBMITTED` or active review; creates only `PENDING`. |
| `GET /reviews/{review_id}/events` | `text/event-stream` | `404` unknown; pending starts/claims executor; running reconnect replays/waits; terminal replay is immutable. |
| `GET /reviews/{review_id}` | `200 ReviewReportResponse` | `404` unknown; `409` if no completed validated report. |
| `POST /approvals` | `201 Approval` | `403` non-approver; `422` invalid payload/blank rejection; `404` unknown review; `409` skipped/repeated/uncompleted decision. |
| `GET /audit` | sorted `list[AuditEvent]` | `422` invalid filters; summaries redacted and capped. |
| `GET /gaps?district_id=` | sorted list or one record | `404` unknown canonical district; `503` missing/malformed gap file; no recalculation/write. |

SSE uses `event: review\ndata: <validated SseEvent JSON>\n\n`. Success is `status → tool_call* → verdict* → done`; failure is `status → tool_call* → error`. All terminal events are stored before delivery. `done.payload` is `{ "review_id": review_id }`; the frontend fetches the persisted `ReviewReportResponse` afterward. Replays produce no provider work and no duplicate audit rows.

`ReviewReportResponse` contains `review_id`, persisted `proposal`, `report`, and `candidates: list[ReviewCandidateDetail]`, where each detail has the final verdict and project resolved by `get_registered_project`. This prevents frontend invention of project identity/provenance. Approval checks `role == approver` in both FastAPI and `SQLiteStore.record_approval` before a write. In one transaction it requires a completed report and `REVIEWED`, creates the approval, changes proposal status to `APPROVED`/`REJECTED`, and writes audit. It invokes no funding behavior. Report redirects are exposed as focus state only; `/gaps` remains derived/read-only.

Audit records append submission, creation, claim/reclaim, tool timing, final verdict, taxonomy downgrade, completion/failure, approval denial, and successful decision. They include factual UTC timestamp, actor/role where applicable, canonical IDs, and sanitized short summary. Expected provider/cache errors log warning with error class and IDs; unexpected errors log server-side with correlation IDs but return generic readable detail. Credential values, secrets, raw request bodies, and stack traces are excluded.

## Frontend

`frontend/` is created as a Vite application with exact `package.json`/`package-lock.json`, strict `tsconfig.json`, Vite/Tailwind/PostCSS config, and `src/` modules. `VITE_API_BASE_URL` defaults to `http://localhost:8000`; frontend commands never start the externally managed API. FastAPI explicitly permits the Vite origin in development.

- `src/types/contracts.ts` mirrors every Pydantic boundary, including proposal `source_url`, report envelope, project provenance, gaps, audit, and SSE. `src/types/parsers.ts` manually validates all REST/SSE data and rejects unknown enums, unknown required-shape changes, invalid dates, nonfinite scores/durations, and incompatible source values before state changes.
- `src/api/clashApi.ts` implements fetch methods and typed `ApiError`. It maps the exact credential 503 error to `credentials-expired`. `src/api/sse.ts` uses cancellable `fetch`/`ReadableStream` parsing; an `AbortController` stops unmount/retry requests, parser failure terminates the reducer, and terminal event closes the reader.
- `src/hooks/useReviewWorkflow.ts` owns reducer stages `idle`, `submitting`, `creating-review`, `streaming`, `complete`, and `error`. It retains form draft on errors, fetches report only after `done`, ignores all post-terminal events, supports reconnect/replay for a known running review, and separately stores `focusedDistrictId` so redirect never mutates gap values.
- `src/pages/PlannerDashboard.tsx` composes `ProposalForm`, `RoleToggle`, `SeededBadge`, `VerdictCard`, `MapWorkspace`, `GapCallout`, `AgentTrace`, `MemoPanel`, and `DecisionDrawer`. Components contain presentation/accessibility, not transport authority.

At 1366×768 the dashboard has an internally scrolling 360px intake/verdict panel, flexible central map, and closed-by-default right drawer that overlays only the map. The drawer traps focus, closes via Escape, and returns focus to its opener. Review streaming always displays nonblank progress. The drawer uses “coordination sign-off” and “coordination focus”; planner users see why approver authority is required. Approve/Reject is enabled only for an approver, persisted `REVIEWED` status, report, and review ID. Rejection requires non-whitespace text.

`MapWorkspace` loads validated static local copies under `frontend/public/data/geo/`, prepared by a small build-copy script from `data/geo/`; browsers do not read repository paths. It renders local GeoJSON, accessible need-score legend/popup, indicator-quality and snapshot labels (`TBD: needs source` when applicable), optional OSM tiles, proposal/candidate markers, and relation lines only if both endpoints have local provenance-labelled coordinates. Missing static data, tile error, or missing coordinates displays a localized map-unavailable/partial-data state while review and approval remain usable. The four verdict colors always have text labels: `DUPLICATE #C0392B`, `OVERLAPPING #D68910`, `COMPLEMENTARY #138D75`, `UNRELATED #7F8C8D`. Candidate cards display identity, funder, provenance/source URL when present, confidence, fact-backed attributes, reasoning, and a map-select action. `SeededBadge` is shown iff proposal/report/project `source` is seeded. Clicking redirect only invokes `focusDistrict`; assertions verify need score, commitments, per-capita funding, and gap classification are unchanged.

## Validation strategy and acceptance evidence

Focused pytest tests cover shared contracts/proposal URL handling, normalized cache identity, canonical registry resolution for both cached candidate IDs and provenance, cache isolation with AWS/Chroma mocks that fail if touched, deterministic overlap/taxonomy, retrieval ordering/filters, provider credential mapping, gap read-only behavior, SQLite transitions/audit, and API response envelopes. SSE tests prove successful order, exactly one terminal event, executor exception, disconnect-before-terminal with eventual replay, cancellation failure handling, expired-lease reclaim, reconnect prefix/remainder ordering, and no post-terminal state mutation. Hypothesis proves date slack boundary/symmetry, cross-city exclusion, duplicate evidence minimum, closed confidence/labels, approval reachability, retrieval uniqueness/order, and redirect immutability.

The cached integration smoke uses temporary SQLite and the public API boundary: seeded POST → review → stream/reconnect-compatible persisted events → completed report → approver action → audit → redirect/gap fetch. It asserts `demo-proposal-01`, one `OVERLAPPING`, one `COMPLEMENTARY`, `CO_FINANCE`, seeded proposal/report/candidate provenance and source URL, canonical tool facts, approver-only transition, and unchanged gap funding/need values after focus. It runs without AWS, Chroma, or MiniLM.

Vitest/React Testing Library cover parsers/transport, credential banner, stream abort/terminal immutability, draft retention, source URL and seeded visibility, label palette/accessible card content, decision authority/rejection reason, drawer focus behavior, map fallback/missing-coordinate omission, and redirect invariance. fast-check covers accepted event terminal safety, all role/status combinations, verdict rendering closure, provenance badge behavior, and map-focus immutability. A mocked canonical UI flow verifies submit → stream → report → Approver → approve → redirect focus. Where browser tooling exists, a 1366×768 smoke checks keyboard operation and drawer open/closed layout.

After implementation, run only focused checks for changed behavior with the repository `.venv` activated: targeted `pytest`/Hypothesis files, `ruff check` and `ruff format --check` on changed Python, `python -m agent.eval --quick`, and `DEMO_MODE=cached python scripts/demo_smoke.py`. Run frontend changed Vitest tests, `npm run typecheck`, and `npm run build`. Check a port before starting any process; reuse the externally managed API on 8000 and run only the frontend on 5173 when free. Checkboxes are updated only after their corresponding validation passes.

## Operational boundaries and deferrals

Cached mode is the required demo delivery and fully offline except optional OSM map tiles. Live Nova/Titan requires valid freshly loaded `agent/.env` credentials, an account-exposed model ID, Chroma, and index/local-model availability. Their absence is a typed readable error, not a reason to compromise cached operation. Full live-provider reachability, local MiniLM cache warming, index rebuild, and browser verification unavailable in the execution environment are operationally deferred only after the cached smoke path passes. No work commits, pushes, rewrites Git history, edits raw data manually, or claims real-world funding/impact.

## Design-review finding responses

1. **Addressed — unified project resolution.** `agent/registry.py:get_registered_project` is now mandatory for tool lookup, overlap facts, report candidate details, cache validation, and coordinate validation. It rejects duplicate IDs instead of choosing a source precedence. Tests prove both seeded cached candidates resolve with preserved provenance.
2. **Addressed — disconnect/cancellation recovery.** Claimed execution is application-owned rather than iterator-owned; events persist before delivery, reconnects replay and wait, and broad task failure/cancellation calls idempotent terminal failure. A persisted lease permits safe recovery of an abandoned `RUNNING` review. Tests cover disconnect, exception, cancellation, reclaim, and sole-terminal invariants.
3. **Addressed — semantic cache identity.** The design explicitly chooses normalized `ProposalCreate` equality/fingerprinting. Whitespace and omitted/default equivalence are accepted; unknown keys/substantive normalized changes fail. Tests document all required presence/normalization cases.
4. **Addressed — proposal source URL.** `source_url` is added to proposal contracts, cache, persistence, response envelope, TypeScript parser, and provenance UI. The seeded scenario requires the explicit `seeded://atlas11/demo-city-transit-01` URI and has display coverage.
5. **Addressed — persisted-proposal handoff.** `CachedScenario` has its canonical proposal ID and `ProposalCreate` body. Intake constructs/persists `Proposal` with server timestamp; execution obtains it from the store and passes it to deterministic tools. Smoke tests assert matching cache/report/stored/tool/event IDs.
